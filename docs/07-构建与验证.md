## 2. 构建步骤

### 方式 A：Android Studio（推荐）

1. `File → Open`，选择工程根目录 `PocketCodeStudio`。
2. 首次打开会自动触发 Gradle Sync；若提示缺少 NDK，按提示安装
   `26.1.10909125`，或修改 `app/build.gradle.kts` 的 `ndkVersion`。
3. 执行 `Build → Make Project`，或直接 `Run 'app'` 安装到设备。

### 方式 B：命令行

```bash
# 需先配置 ANDROID_HOME / ANDROID_SDK_ROOT 指向本地 SDK
./gradlew assembleDebug           # 产出 app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:externalNativeBuildDebug   # 仅编译 JNI 原生库
```

> ⚠️ `gradlew` 的可执行位（+x）在 FUSE 挂载的 `/sdcard` 上无法保存。
> 若从手机直接拷贝，请在 PC 端执行一次 `chmod +x gradlew`，或改用 `sh gradlew ...`。

## 4. JNI 符号名对齐（关键修复）

**背景**：`external fun` 若声明在 `companion object` 中，部分 Kotlin 版本会将其
JNI 符号名生成为 `Java_<pkg>_<Outer>_00024Companion_<method>`（`$` 编码为 `_00024`），
与 C 侧手写的符号名不匹配，导致运行时 `UnsatisfiedLinkError`。

**方案**：把 JNI 绑定层抽到独立单例 `object PcsTerm`，符号名稳定为
`Java_com_pocketcode_studio_core_terminal_PcsTerm_<method>`。

三处已严格同步：

| 位置 | 内容 |
| --- | --- |
| `PcsTerm.kt` | `object PcsTerm` 声明 5 个 `external fun` 并 `loadLibrary("pcs_term")` |
| `TerminalService.kt` | 全部改调 `PcsTerm.nativeXxx(...)`，移除旧的 `external` 声明与 `loadLibrary` |
| `term.cpp` | 5 个函数名前缀统一为 `Java_com_pocketcode_studio_core_terminal_PcsTerm_nativeXxx` |

> 维护提示：今后**新增原生方法**时，必须同时改这三处，缺一处即崩。

## 5. 残余风险清单（需在首次构建时验证）

以下项在无 SDK 环境下**无法本机验证**，列出以便首次 Sync/编译时快速定位：

1. **第三方依赖解析**：libsu 5.2.2 走 JitPack、Sora Editor 0.23.5 走 Maven Central，
   若某坐标不存在，需按报错调整版本号。
2. **Material3 API 适配**：`ScrollableTabRow(edgePadding=...)`、`HorizontalDivider`
   在 Material3 1.3.0（BOM 2024.09.00）下预期可用，若报错按提示调整。
3. **QuickJS 反射签名**：插件引擎通过反射调 QuickJS，不同版本类名可能变化，
   运行期验证。
4. **NDK / CMake**：`forkpty` 依赖 `<pty.h>`，需确认所选 NDK 版本提供该头文件。
