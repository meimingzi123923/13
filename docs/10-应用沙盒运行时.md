# 10 · 应用沙盒运行时

## 问题

早期版本的执行链路：

```
BuildRunService.run()
  → 命令 "python3 main.py"
  → TerminalService（forkpty）→ /system/bin/sh -c "python3 main.py"
```

Android 系统的 `/system/bin/sh` 里**没有** python3 / node / gcc 等解释器，
所以无论用户写什么程序，执行必然失败。**程序跑不起来不是代码写错，而是运行时缺失。**

## 方案：把运行时放进 App 私有沙盒

不再依赖系统环境，改为在 **App 私有目录 `filesDir/sandbox`** 内执行：

```
filesDir/sandbox/
  bin/   可执行文件（python3、node、gcc、g++、go …）
  lib/   运行库（LD_LIBRARY_PATH）
  tmp/   临时目录（TMPDIR）
```

执行命令时注入环境前缀（`SandboxRuntime.envPrefix()`）：

```sh
cd '<projectDir>' && \
  PATH='<sandbox>/bin':"$PATH" \
  LD_LIBRARY_PATH='<sandbox>/lib':"$LD_LIBRARY_PATH" \
  TMPDIR='<sandbox>/tmp' HOME='<sandbox>' \
  python3 main.py
```

这样 `python3` 会先命中沙盒里的内置运行时。

## 组件

| 文件 | 职责 |
|---|---|
| `core/sandbox/SandboxRuntime.kt` | 沙盒目录管理、assets 释放、工具解析、环境前缀、zip 导入 |
| `core/sandbox/JsSandbox.kt` | 进程内 QuickJS 沙盒（JS 无需外部二进制） |
| `core/build/BuildRunService.kt` | 释放运行时 → JS 走 QuickJS → 其它语言走沙盒 PATH 的 PTY |

## 运行时来源

1. **APK 内置**：`assets/runtimes/bin`、`assets/runtimes/lib`，
   首次执行时由 `ensureExtracted()` 释放并 `chmod +x`（幂等）。
2. **运行时安装包**：`installFromZip(zip)`，zip 内 `bin/**`、`lib/**` 原样解出。
3. **单文件导入**：`importExecutable(file, name)`。

`assets/runtimes/` 目前随包携带一份 `README.md` 说明放置约定；
把真正的运行时二进制（Android arm64-v8a ELF）放进 `assets/runtimes/bin/` 即可随 APK 分发。

## JavaScript：开箱即用

`.js` 默认**不需要 node**：由 QuickJS 在 App 进程内执行，
`console.log/info/warn/error` 与 `pcs.print` 的输出回送到终端。
只有沙盒里存在 `bin/node` 时才会改用 node。

## 后续可扩展

- 在线下载运行时（App 已有 INTERNET 权限），落盘后调用 `installFromZip`。
- UI 增加「运行时管理」页：列出 `installedTools()`、导入 zip / 单文件。
- 为 C/C++ 打包 toolchain（gcc 本体 + cc1 + as + ld）时保持相对目录结构，
  统一释放到 `bin/`，必要时补 `lib/`。
