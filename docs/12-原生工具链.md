# 12 · 原生工具链（无 proot）

> 状态：**已落地**。本方案取代 docs/11（proot + Alpine，已废弃删除）。

## 1. 目标

让 App 在**没有任何 root、没有 proot、没有 rootfs** 的情况下，直接在手机本地编译并运行 C / C++。

## 2. 结论：可行，且已在真机验证

工具链来自 **Termux aarch64 官方 .deb**，本质是一套「Android 原生（bionic）CLANG 工具链」：

- 入口解释器 `PT_INTERP = /system/bin/linker64`（设备自带，Android 10+ 起系统强制）；
- 依赖的动态库放在可执行文件旁边的 `../lib`，用 `LD_LIBRARY_PATH` 指向即可；
- clang / lld 对 Termux 前缀（`/data/data/com.termux/files/usr`）的硬编码只有 RUNPATH / 默认搜索路径，
  全部可以被 `-B / -L / -isystem / -fuse-ld` 与环境变量覆盖。

真机实测（arm64 Android）：

```sh
LD_LIBRARY_PATH=<tc>/lib <tc>/bin/clang-21 \
  -fuse-ld=lld -B<tc>/bin -L<tc>/lib -isystem <tc>/include \
  hello.c -o hello
./hello          # 输出 hello from android clang，exit=0
```

## 3. 为什么把 `.deb` 原样打进 assets

1. **体积可控**：15 个包合计约 83 MB，单文件均 < 100 MB，可直接进 git（无需 LFS）；
2. **保留权限与软链**：deb 内部是 `ar + data.tar.xz`，tar 天然保留**符号链接与执行位**。
   散文件放进 assets 会丢失这两者——实测 `/sdcard` 的 FUSE 不保留 symlink 与 exec 位，
   会导致 clang 起不来。

## 4. 目录与命名

```
app/src/main/assets/toolchain/
  clang.deb  libllvm.deb  lld.deb  llvm.deb  libcxx.deb  libcompiler-rt.deb
  ndk-sysroot.deb  zlib.deb  zstd.deb  liblzma.deb  libxml2.deb  libffi.deb
  libiconv.deb  libandroid-glob.deb  ncurses.deb
```

（clangd 由 `clang.deb` 自带，已保留，供编辑器补全。）

## 5. 运行时释放（NativeToolchain.kt）

解压到 `filesDir/sandbox/tc/`：

```
filesDir/sandbox/
  tc/bin  tc/lib  tc/include  tc/libexec  tc/share
  tmp/
```

流程：`deb(ar)` → 找 `data.tar` → `XZCompressorInputStream` → `TarArchiveInputStream` → 写文件，
剥掉 Termux 前缀 `data/data/com.termux/files/usr/`，软链绝对路径转相对路径（保证可重定位），
再补建必要软链与包装脚本：

- `clang-21 → clang / clang++`（Termux 不提供裸名 `clang`）
- `lld → ld.lld / ld`
- `include/asm → aarch64-linux-android/asm`
- `gcc / cc → clang-21`、`g++ / c++ → clang++` 包装脚本（自动注入
  `-fuse-ld=lld -B<bin> -L<lib> -isystem <include> -Wl,-rpath,<lib>`）

完成后写 `tc/.ready` 标记，幂等。

> 依赖：Kotlin 侧用 `org.apache.commons:commons-compress` + `org.tukaani:xz` 解 `.tar.xz`。

## 6. 执行链

`BuildRunService` 对 `c / cpp` 语言：

```
cd <projectDir> && PATH=<tc>/bin:... LD_LIBRARY_PATH=<tc>/lib:... TMPDIR=<sandbox>/tmp HOME=<tc> \
  gcc main.c -o a.out && ./a.out
```

命令写进 `TerminalService` 的 PTY（`libpcs_term` → `term.cpp` forkpty → `sh -c`）。

## 7. 重要约束：targetSdk = 28

Android 10（API 29）起，对 `targetSdk >= 29` 的应用启用 **W^X**，会**禁止 execve 应用私有目录中的可执行文件**。
工具链必须执行，因此本 App 保持 `targetSdk = 28`（`minSdk = 26`）。
这是「本地编译」能力的前提，代价是侧载开发工具、无法上架新目标版本商店。

## 8. 与旧方案对比

| 维度 | proot + Alpine（docs/11，已删） | 原生工具链（本方案） |
| --- | --- | --- |
| 启动开销 | 每次 fork proot，慢 | 无，直接 exec |
| 体积 | rootfs + proot | 约 150 MB 解压后 |
| 依赖 | 自带 Linux rootfs | 系统 linker64 + bionic |
| 稳定性 | bind mount / TMPDIR 坑多 | 纯原生，坑少 |
| clangd 补全 | 无 | 有 |

## 9. 其它语言

- JavaScript：App 进程内 QuickJS（`JsSandbox`），无需外部二进制；
- Python / Node / Go / Rust …：本方案未内置，回退到 `SandboxRuntime` 的
  「用户自备运行时导入」（`installFromZip` / `importExecutable`）。
